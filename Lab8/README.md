## Выбор структур данных и пояснения

- **Почему запись удобно представить словарём (`dict`):** поля записи имеют явные имена (`title`, `hours`, `completed`), поэтому обращаться к данным по ключу читаемее, чем по числовому индексу, а новые поля можно добавлять без смещения позиций остальных элементов.
- **Частоты слов и сводки по категориям (`dict`):** словарь удобно сопоставляет ключ (слово или категорию) накопленному значению (счётчику или сумме).
- **Учебные интересы (`set`):** множества убирают повторяющиеся темы и позволяют в одно действие найти пересечение (`&`) и объединение (`|`).
- **Пары значений (`tuple`):** кортеж фиксирует пару элементов (например, `(title, hours)` или `(category, total)`), которую удобно распаковать в переменные.
- **Списки записей и результатов (`list`):** сохраняют исходный порядок элементов при фильтрации и не мутируются при подсчёте сумм.
- **Поведение `.get(key, default)`:** возвращает значение по ключу, если оно есть, либо значение `default` (например, `0`), если ключа ещё нет, позволяя не писать лишние проверки наличия ключа и избегать `KeyError`.
- **Зачем сортировать множество перед выводом:** у `set` нет индексов и гарантированного порядка обхода; `sorted(...)` возвращает упорядоченный список для воспроизводимого вывода и стабильных проверок.
- **Дополнительное задание (`sorted` с `key`):** `key=lambda pair: (-pair[1], pair[0])` сортирует пары `(category, total)` сначала по убыванию `amount` (за счёт знака минус), а при равенстве сумм — по названию категории по алфавиту.
