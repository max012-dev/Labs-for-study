## Формат входных данных и правила валидации

Файл `todos.json` читается в кодировке `UTF-8` через `json.load`. Функция `validate_todos(data)` проверяет не только синтаксис JSON, но и ожидаемую структуру данных:

1. Корень документа должен быть списком (`list`).
2. Каждый элемент списка должен быть объектом/словарём (`dict`). Допускаются дополнительные ключи, но обязательны:
   - `id` — положительное целое число (`type(value) is int` и `value > 0`), уникальное в пределах всего списка;
   - `userId` — положительное целое число (`type(value) is int` и `value > 0`);
   - `title` — непустая строка (`type(value) is str` и `bool(value.strip())`);
   - `completed` — строго логическое значение (`type(value) is bool`).
3. При любом нарушении выбрасывается `ValueError` с понятным пояснением.

### Почему используется строгая проверка типов (`type(...) is ...`)

В Python тип `bool` является подклассом `int`, поэтому выражение `isinstance(True, int)` возвращает `True`. Проверка `type(value) is int` не пропускает булевы значения в числовые поля (`id`, `userId`), а `type(value) is bool` отсекает строки вроде `"false"` или числа `0`/`1` в поле `completed`.

## Обработка ошибок и сохранение результатов

В `main.py` чтение и проверка `todos.json` выполняются до записи выходных файлов `leaders.json` и `selected.json`:

- Если входной файл отсутствует (`FileNotFoundError`), повреждена кодировка (`UnicodeError`), нарушен синтаксис JSON (`json.JSONDecodeError`), не проходит проверка структуры (`ValueError`) или возникает ошибка файловой системы (`OSError`), программа выводит сообщение об ошибке и завершается **без перезаписи** ранее созданных `leaders.json` и `selected.json`.
- Обработчик `json.JSONDecodeError` ставится **раньше** общего `ValueError`, поскольку `JSONDecodeError` является наследником `ValueError`. Разделение этих веток позволяет чётко отличать битый синтаксис JSON от некорректной структуры данных.
- Идентификаторы пользователей остаются целыми числами (`int`) при сравнении и сортировке; преобразование в строки применяется только при форматировании текстового вывода. Исходные словари в списках при фильтрации не мутируются.

## HTTP-упражнение: профиль GitHub и локальный пример

Модуль `fetch_profile.py` не выполняет сетевых запросов при импорте — всё запускается в `main()`. Добавлено консольное меню выбора источника: **сеть (GitHub API)** или **локальный пример (`profile_sample.json`)**, а для отображения данных используется единая функция `print_profile()`.

### Назначение элементов запроса и обработки ошибок

- **Адрес запроса (`https://api.github.com/users/<login>`):** обращается к ресурсу профиля пользователя GitHub, а не репозитория (для репозитория потребовались бы владелец и имя репозитория). Логин очищается через `.strip()` и экранируется в пути через `urllib.parse.quote(..., safe="")`.
- **Метод `GET`:** запрашивает представление ресурса у сервера без изменения данных на стороне сервера.
- **Таймаут (`timeout=10`):** ограничивает ожидание ответа сети, чтобы программа не зависала при обрыве связи или медленном ответе сервера.
- **Обработчики исключений:**
  - `HTTPError` — перехватывает ответы сервера с ошибкой HTTP (например, `404` при несуществующем логине или `403`/`429` при ограничениях доступа/частоты запросов);
  - `(URLError, TimeoutError, socket.timeout)` — обрабатывает сетевые сбои, недоступность хоста и превышение времени ожидания;
  - `(ValueError, UnicodeError, json.JSONDecodeError)` — ловит пустой логин, ошибки декодирования текста, невалидный JSON или неожиданную структуру ответа;
  - `OSError` — обрабатывает ошибки файловой системы при сохранении `profile.json` или чтении локального примера.

### Работа без доступа к сети

Если интернет недоступен или выбран локальный режим (`2`), программа читает `profile_sample.json` через `json.load` и выводит логин и поля профиля. Поле `"name": null` в JSON загружается как `None` и **не заменяется** выдуманными данными. В отчёте фиксируется использование учебных локальных данных.

## Фактический режим запуска HTTP-упражнения

- Если запрос к `https://api.github.com/users/octocat` выполнен при наличии сети: в `README` указывается факт успешного получения ответа и сохранения `profile.json` без жёсткой привязки к изменяемым полям профиля.
- Если сеть недоступна или выбран пункт `2` в меню: использован локальный файл `profile_sample.json` (`{"login": "demo", "id": 1, "name": null}`), прочитанный через `json.load` с выводом логина и сохранением значения `null` (`None`) без подстановки выдуманных данных.
