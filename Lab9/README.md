## Ответы на вопросы к защите

- **Какую ошибку выявляет таблица `2x3`:** на квадратной таблице легко не заметить путаницу между числом строк (`len(matrix)`) и числом столбцов (`len(matrix[0])`), а также перепутать порядок индексов `matrix[row][column]` и `matrix[column][row]`. На прямоугольной матрице `2x3` ошибка сразу проявляется через `IndexError` при выходе за границы строки/столбца или через неверные суммы при перепутанных вложенных циклах.
- **Почему нельзя создавать таблицу как `[[0] * columns] * rows`:** умножение списка на число копирует ссылки на объекты, а не создаёт новые списки. Все строки внешнего списка будут указывать на один и тот же внутренний список, поэтому изменение ячейки в одной строке затронет все остальные строки.
- **Чем копия внешнего списка отличается от копирования строк:** `matrix.copy()` создаёт только новый внешний список, но внутренние списки-строки остаются общими (изменение `copy_matrix[0][0]` затронет исходную таблицу). Выражение `[row.copy() for row in matrix]` создаёт новый внешний список и копирует каждую строку отдельно, поэтому изменение элементов в новой таблице не меняет исходную.
- **Преобразование варианта 14 (`transform`):** создаётся новая матрица той же формы, где для каждого элемента проверяется условие `-2 <= value <= 3`; подходящие значения возводятся в квадрат, остальные сохраняются без мутации исходной матрицы.

## Дополнительный модуль: рекурсия

Рекурсивная функция вызывает саму себя, опираясь на базовый случай остановки и шаг, приближающий аргумент к нему.

### Трассировка `factorial(3)`

1. Вызовы (прямой ход):
   - `factorial(3)` -> вызывает `3 * factorial(2)`
   - `factorial(2)` -> вызывает `2 * factorial(1)`
   - `factorial(1)` -> вызывает `1 * factorial(0)`
   - `factorial(0)` -> базовый случай, возвращает `1`
2. Возвраты (обратный ход):
   - `factorial(0)` возвращает `1`
   - `factorial(1)` вычисляет `1 * 1` -> возвращает `1`
   - `factorial(2)` вычисляет `2 * 1` -> возвращает `2`
   - `factorial(3)` вычисляет `3 * 2` -> возвращает `6`

Увеличивать лимит глубины рекурсии не следует: слишком глубокая цепочка вызовов приведёт к `RecursionError`. Для чисел от `0` до `20` рекурсивная и итеративная версии возвращают одинаковые значения.
